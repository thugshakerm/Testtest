Foundations

What all three revivals share. Every one of them is Laravel + Bootstrap + Source Sans Pro + Font Awesome — that combination is the Laravel UI preset, so the shared "ORC look" is mostly an inherited default that nobody substantially redesigned. Understanding that is the key to reading everything below: the differences are in brand colour, nav structure, and currency presentation, not in a fundamentally different design language.

Colour palettes

Three different inherited palettes. Kapish's is the Laravel Nova preset, not Bootstrap's defaults — that indigo/purple/pink family is where the genre's look comes from. Finobe's is Chakra UI semantics layered on Bootstrap 4 grays.

Typography

Source Sans Pro everywhere. Only the Tadah rewrite bundles fonts locally; the other two hotlink Google Fonts and a paid Font Awesome CDN kit.

Type stacks

Role: Kapish and the Tadah rewrite use a single family. Finobe runs a two-tier stack — proxima-nova for headings, Source Sans Pro for everything else — with real CJK fallbacks, which is unusual thoroughness for a revival.

Headings — proxima-nova

Body copy — Source Sans Pro at 0.9rem / 1.6, which is denser than Bootstrap's default 1rem / 1.5 and is the single biggest reason these sites feel like 2010s game sites rather than modern web apps.

Kapish · Tadah legacy Laravel 8 + Bootstrap 4

Kapish is Tadah rebranded — proven, not assumed: both Casenn05/tadah-site-classic and conewasnthere/kapish-web-trunk declare "name": "tadah/tadah" in composer.json, and the package name survived the rebrand. Kapish's own README is titled "Kapish Website (formerly Tadah)" and its footer links discord.gg/kapish beside gitlab.com/tadah. Tadah started August 2021 and was replaced by the rewrite in February 2022. This is the most complete and most representative design of the three.

function updateCountdown() {
  var distance  = targetDate - Date.now();
  var hours     = Math.abs(Math.floor((distance % 864e5) / 36e5));
  var minutes   = Math.abs(Math.floor((distance % 36e5)  / 6e4));
  var seconds   = Math.abs(Math.floor((distance % 6e4)   / 1e3));
  var text = hours + 'h ' + minutes + 'm ' + seconds + 's remaining';
  $('.tooltip-inner').text(text);
  $('[data-original-title]').attr('data-original-title', text);
}
setInterval(updateCountdown, 1000);

Two bugs to fix if you copy this: the selector $('[data-original-title]') matches every tooltip on the page, and userTimezone is computed then never used. Scope the selector to the pill and either use the timezone or delete the line. Also note the original spells "remaining" as "remaning".

Landing page

Role: a full-bleed marketing page with no site chrome at all — no navbars, no footer, no ads. Implemented by branching the main layout on a $landing variable, with a fullscreen fixed background video behind the copy.

  @isset ($landing)
    @yield('content')
  @else
    <!-- navbar, sub-nav, alerts, ads, main, footer -->
  @endisset

<!-- the title also changes shape -->
@isset ($landing)
  <title>{{ config('app.name') }}</title>
@else

/* fullscreen fixed background video */
.landing-page video {
  position: fixed; z-index: -1; top: 0;
  width: 100%; min-width: 100%; min-height: 100%;
  object-fit: cover; opacity: 1;
}

Weakness: @isset($landing) wraps roughly 90% of a 200-line template in an @else. The Tadah rewrite solves the identical problem with a single $fluff boolean in a Blade component — see Tadah navbar.

Accessibility: z-index: -1 on the video puts it behind the page background in some stacking contexts, and a fixed fullscreen video is a known prefers-reduced-motion hazard. Wrap it in a media query.

Finobe uses the identical pattern (its v1 nav even renders a permanent deprecation banner). Cheap to add, impossible to ignore, and the reason these sites could communicate outages without a status page.

XSS risk: Finobe renders these with {{ announcement.message | raw }} and Kapish pipes them through @parsedown. Both bypass escaping. If an admin account is compromised, that becomes stored XSS on every page. Escape the text and allowlist markup instead.

Motto text outline

Role: the old-Roblox look. White text with a 1px black outline on all four diagonals, used for user "status" strings over avatars and on landing heroes. It is the cheapest way to make text readable over any image.

Building the future, one brick at a time.

    Lazy thumbnails via data attributes steal this

    Role: the single most portable pattern in the whole study. Every image ships a placeholder in src plus the real identity in data-* attributes; one global script swaps them. The server never blocks on a thumbnail render, the page paints immediately, and the markup stays declarative. Kapish uses data-tadah-thumbnail-id / data-tadah-thumbnail-type on every image in the app — places, items, headshots, full-body thumbnails.

    Click any image — the script swaps src from data-sg-thumb, exactly as the real sites do on load.

<img src="{{ asset('images/thumbnail/blank_place.png') }}"
     data-tadah-thumbnail-id="{{ $server->uuid }}"
     data-tadah-thumbnail-type="place-thumbnail"
     alt="{{ $server->name }} thumbnail">

place-thumbnail | item-thumbnail | user-headshot | user-thumbnail

// the global context the swap script reads
<script type="text/javascript">
  tadah = { baseUrl: "{{ config('app.url') }}" };
  @if (Auth::check()) tadah.session = { userId: {{ Auth::user()->id }} }; @endif
</script>

// the swap — use IntersectionObserver rather than eager loading
const io = new IntersectionObserver((entries) => {
  for (const e of entries) {
    if (!e.isIntersecting) continue;
    const img = e.target;
    const url = `${tadah.baseUrl}/thumbnail/`
              + `${img.dataset.tadahThumbnailType}/`
              + `${img.dataset.tadahThumbnailId}`;
    const pre = new Image();
    pre.onload  = () => { img.src = url; img.removeAttribute('data-tadah-thumbnail-id'); };
    pre.src = url;                    // keep the placeholder until it decodes
    io.unobserve(img);
  }
}, { rootMargin: '200px' });

document.querySelectorAll('[data-tadah-thumbnail-id]').forEach(el => io.observe(el));

    Two details that make it work: preload into a detached Image() and only assign src on onload, so the placeholder never flashes away to reveal a half-decoded image. And remove the data attribute once swapped, so a re-render does not re-fetch.

    Modern shorthand: if you control the server, loading="lazy" + srcset gets you most of this for free. Keep the data-attribute approach only if you need to swap in a rendered thumbnail asynchronously, which is the actual use case here.
